# 고객 스토리 (Customer Stories)

---

## CS-01: 테이블 자동 로그인
**As a** 고객 (김민수),
**I want** 테이블 태블릿에서 별도 로그인 절차 없이 자동으로 인증되기를,
**So that** 앉자마자 바로 메뉴를 탐색하고 주문할 수 있다.

### Acceptance Criteria
**Scenario 1: 초기 설정 완료된 태블릿에서 자동 로그인**
- Given: 관리자가 태블릿에 매장 식별자, 테이블 번호, 비밀번호를 설정하고 최초 로그인에 성공한 상태
- When: 고객이 태블릿 브라우저에서 서비스에 접속한다
- Then: 저장된 인증 정보로 자동 로그인되어 메뉴 화면이 표시된다

**Scenario 2: 자동 로그인 실패 시**
- Given: 저장된 인증 정보가 유효하지 않은 상태 (비밀번호 변경 등)
- When: 자동 로그인이 시도된다
- Then: 초기 설정 화면이 표시되어 관리자가 재설정할 수 있다

---

## CS-02: 카테고리별 메뉴 목록 조회
**As a** 고객 (김민수),
**I want** 카테고리별로 분류된 메뉴 목록을 카드 형태로 보기를,
**So that** 원하는 종류의 메뉴를 쉽게 찾을 수 있다.

### Acceptance Criteria
**Scenario 1: 메뉴 화면 진입**
- Given: 자동 로그인이 완료된 상태
- When: 기본 화면이 로드된다
- Then: 카테고리별로 분류된 메뉴가 카드 형태로 표시되며, 각 카드에 메뉴명, 가격, 이미지가 표시된다

**Scenario 2: 특정 카테고리 선택**
- Given: 메뉴 화면이 표시된 상태
- When: 특정 카테고리를 선택한다
- Then: 해당 카테고리의 메뉴만 필터링되어 표시된다

---

## CS-03: 메뉴 상세 정보 조회
**As a** 고객 (김민수),
**I want** 메뉴 카드를 클릭하여 상세 정보(설명, 이미지, 가격)를 보기를,
**So that** 주문 전에 메뉴에 대해 충분히 파악할 수 있다.

### Acceptance Criteria
**Scenario 1: 메뉴 상세 보기**
- Given: 메뉴 목록이 표시된 상태
- When: 특정 메뉴 카드를 클릭한다
- Then: 메뉴명, 가격, 설명, 이미지가 포함된 상세 정보가 표시된다

---

## CS-04: 카테고리 간 빠른 이동
**As a** 고객 (김민수),
**I want** 카테고리 탭이나 네비게이션을 통해 다른 카테고리로 빠르게 이동하기를,
**So that** 여러 카테고리의 메뉴를 효율적으로 탐색할 수 있다.

### Acceptance Criteria
**Scenario 1: 카테고리 이동**
- Given: 특정 카테고리의 메뉴를 보고 있는 상태
- When: 다른 카테고리 탭을 클릭한다
- Then: 해당 카테고리의 메뉴 목록으로 즉시 이동한다

---

## CS-05: 장바구니에 메뉴 추가
**As a** 고객 (김민수),
**I want** 원하는 메뉴를 장바구니에 추가하기를,
**So that** 여러 메뉴를 선택한 후 한 번에 주문할 수 있다.

### Acceptance Criteria
**Scenario 1: 메뉴 추가**
- Given: 메뉴 목록 또는 상세 화면이 표시된 상태
- When: 메뉴의 추가 버튼을 클릭한다
- Then: 해당 메뉴가 수량 1로 장바구니에 추가되고, 총 금액이 업데이트된다

**Scenario 2: 이미 장바구니에 있는 메뉴 추가**
- Given: 장바구니에 해당 메뉴가 이미 존재하는 상태
- When: 같은 메뉴의 추가 버튼을 클릭한다
- Then: 해당 메뉴의 수량이 1 증가하고, 총 금액이 업데이트된다

---

## CS-06: 장바구니 수량 조절
**As a** 고객 (김민수),
**I want** 장바구니에서 메뉴의 수량을 증가/감소시키기를,
**So that** 원하는 만큼의 수량을 정확하게 주문할 수 있다.

### Acceptance Criteria
**Scenario 1: 수량 증가**
- Given: 장바구니에 메뉴가 있는 상태
- When: 수량 증가(+) 버튼을 클릭한다
- Then: 해당 메뉴의 수량이 1 증가하고, 총 금액이 재계산된다

**Scenario 2: 수량 감소**
- Given: 장바구니에 수량이 2 이상인 메뉴가 있는 상태
- When: 수량 감소(-) 버튼을 클릭한다
- Then: 해당 메뉴의 수량이 1 감소하고, 총 금액이 재계산된다

**Scenario 3: 수량 1에서 감소**
- Given: 장바구니에 수량이 1인 메뉴가 있는 상태
- When: 수량 감소(-) 버튼을 클릭한다
- Then: 해당 메뉴가 장바구니에서 제거되고, 총 금액이 재계산된다

---

## CS-07: 장바구니 항목 삭제 및 비우기
**As a** 고객 (김민수),
**I want** 장바구니에서 특정 메뉴를 삭제하거나 전체를 비우기를,
**So that** 주문 내용을 자유롭게 수정할 수 있다.

### Acceptance Criteria
**Scenario 1: 특정 항목 삭제**
- Given: 장바구니에 메뉴가 있는 상태
- When: 특정 메뉴의 삭제 버튼을 클릭한다
- Then: 해당 메뉴가 장바구니에서 제거되고, 총 금액이 재계산된다

**Scenario 2: 장바구니 전체 비우기**
- Given: 장바구니에 1개 이상의 메뉴가 있는 상태
- When: 장바구니 비우기 버튼을 클릭한다
- Then: 모든 메뉴가 장바구니에서 제거되고, 총 금액이 0원으로 표시된다

## CS-08: 장바구니 로컬 저장
**As a** 고객 (김민수),
**I want** 장바구니 내용이 페이지를 새로고침해도 유지되기를,
**So that** 실수로 페이지를 닫거나 새로고침해도 선택한 메뉴를 잃지 않는다.

### Acceptance Criteria
**Scenario 1: 새로고침 후 장바구니 유지**
- Given: 장바구니에 메뉴가 담긴 상태
- When: 브라우저를 새로고침한다
- Then: 장바구니의 메뉴 목록과 수량이 그대로 유지된다

---

## CS-09: 주문 확정
**As a** 고객 (김민수),
**I want** 장바구니의 내용을 최종 확인하고 주문을 확정하기를,
**So that** 정확한 주문을 매장에 전달할 수 있다.

### Acceptance Criteria
**Scenario 1: 주문 확정**
- Given: 장바구니에 1개 이상의 메뉴가 있는 상태
- When: 주문 확정 버튼을 클릭한다
- Then: 주문 내역(메뉴명, 수량, 단가, 총 금액)이 최종 확인 화면에 표시되고, 확정 후 서버로 주문이 전송된다

**Scenario 2: 빈 장바구니에서 주문 시도**
- Given: 장바구니가 비어있는 상태
- When: 주문 확정 버튼을 클릭한다
- Then: 주문이 불가하다는 안내 메시지가 표시된다

---

## CS-10: 주문 성공 후 처리
**As a** 고객 (김민수),
**I want** 주문이 성공하면 주문 번호를 확인하고 자동으로 메뉴 화면으로 돌아가기를,
**So that** 추가 주문을 바로 할 수 있다.

### Acceptance Criteria
**Scenario 1: 주문 성공**
- Given: 주문이 서버에 성공적으로 전송된 상태
- When: 서버에서 성공 응답을 받는다
- Then: 주문 번호가 표시되고, 장바구니가 자동으로 비워지며, 메뉴 화면으로 자동 리다이렉트된다

---

## CS-11: 주문 실패 처리
**As a** 고객 (김민수),
**I want** 주문이 실패하면 에러 메시지를 보고 장바구니가 유지되기를,
**So that** 다시 주문을 시도할 수 있다.

### Acceptance Criteria
**Scenario 1: 주문 실패**
- Given: 주문 전송 중 오류가 발생한 상태
- When: 서버에서 실패 응답을 받는다
- Then: 에러 메시지가 표시되고, 장바구니의 내용은 그대로 유지된다

---

## CS-12: 현재 세션 주문 내역 조회
**As a** 고객 (김민수),
**I want** 현재 테이블 세션에서 주문한 내역을 확인하기를,
**So that** 지금까지 주문한 메뉴와 총 금액을 파악할 수 있다.

### Acceptance Criteria
**Scenario 1: 주문 내역 조회**
- Given: 현재 세션에서 1건 이상의 주문이 있는 상태
- When: 주문 내역 화면에 접근한다
- Then: 현재 세션의 주문만 시간 순으로 표시되며, 각 주문의 번호, 시각, 메뉴 목록, 금액이 표시된다

**Scenario 2: 주문 내역 없음**
- Given: 현재 세션에서 주문이 없는 상태
- When: 주문 내역 화면에 접근한다
- Then: 주문 내역이 없다는 안내 메시지가 표시된다

**Scenario 3: 이전 세션 주문 제외**
- Given: 이전 세션의 주문 이력이 존재하는 상태
- When: 주문 내역 화면에 접근한다
- Then: 이전 세션의 주문은 표시되지 않고, 현재 세션의 주문만 표시된다

---

## CS-13: 주문 상태 확인

- Given: 주문 내역 화면이 표시된 상태
- When: 주문 목록을 확인한다
- Then: 각 주문에 현재 상태(대기중/준비중/완료)가 시각적으로 구분되어 표시된다

# 관리자 스토리 (Admin Stories)

## AS-01: 관리자 로그인
**As a** 관리자 (박서연),
**I want** 매장 식별자, 사용자명, 비밀번호로 관리 시스템에 로그인하기를,
**So that** 매장의 주문과 메뉴를 관리할 수 있다.

### Acceptance Criteria
**Scenario 1: 로그인 성공**
- Given: 유효한 관리자 계정이 존재하는 상태
- When: 올바른 매장 식별자, 사용자명, 비밀번호를 입력하고 로그인 버튼을 클릭한다
- Then: JWT 토큰이 발급되고, 관리자 대시보드로 이동한다

**Scenario 2: 로그인 실패**
- Given: 관리자 로그인 화면이 표시된 상태
- When: 잘못된 인증 정보를 입력하고 로그인 버튼을 클릭한다
- Then: 로그인 실패 메시지가 표시되고, 로그인 화면이 유지된다

**Scenario 3: 로그인 시도 제한**
- Given: 연속으로 로그인에 실패한 상태
- When: 제한 횟수를 초과하여 로그인을 시도한다
- Then: 일정 시간 동안 로그인이 차단되고, 차단 안내 메시지가 표시된다

---

## AS-02: 관리자 세션 유지 및 자동 로그아웃
**As a** 관리자 (박서연),
**I want** 로그인 후 16시간 동안 세션이 유지되고, 이후 자동 로그아웃되기를,
**So that** 영업 시간 동안 반복 로그인 없이 사용하면서도 보안이 유지된다.

### Acceptance Criteria
**Scenario 1: 세션 유지**
- Given: 관리자가 로그인한 상태
- When: 브라우저를 새로고침한다
- Then: 세션이 유지되어 로그인 상태가 계속된다

**Scenario 2: 자동 로그아웃**
- Given: 관리자가 로그인한 지 16시간이 경과한 상태
- When: 다음 요청을 보낸다
- Then: 자동으로 로그아웃되고, 로그인 화면으로 이동한다

---

## AS-03: 실시간 주문 목록 확인
**As a** 관리자 (박서연),
**I want** 들어오는 주문을 실시간으로 테이블별 그리드 형태로 확인하기를,
**So that** 모든 테이블의 주문 상황을 한눈에 파악할 수 있다.

### Acceptance Criteria
**Scenario 1: 대시보드 표시**
- Given: 관리자가 로그인한 상태
- When: 대시보드 화면에 접근한다
- Then: 테이블별 카드가 그리드 형태로 표시되며, 각 카드에 테이블 번호, 총 주문액, 최신 주문 미리보기가 표시된다

**Scenario 2: 실시간 업데이트**
- Given: 대시보드가 표시된 상태
- When: 고객이 새로운 주문을 생성한다
- Then: 2초 이내에 해당 테이블 카드에 새 주문이 반영된다

---

## AS-04: 주문 상세 보기
**As a** 관리자 (박서연),
**I want** 테이블 카드를 클릭하여 해당 테이블의 전체 주문 목록을 상세히 보기를,
**So that** 각 주문의 메뉴, 수량, 금액을 정확히 확인할 수 있다.

### Acceptance Criteria
**Scenario 1: 주문 상세 보기**
- Given: 대시보드에 테이블 카드가 표시된 상태
- When: 특정 테이블 카드를 클릭한다
- Then: 해당 테이블의 전체 주문 목록이 표시되며, 각 주문의 번호, 시각, 메뉴 목록, 수량, 금액, 상태가 표시된다

## AS-05: 주문 상태 변경
**As a** 관리자 (박서연),

### Acceptance Criteria
**Scenario 1: 상태 변경**
- Given: 주문 상세 화면에서 특정 주문이 표시된 상태
- When: 주문 상태 변경 버튼을 클릭한다
- Then: 주문 상태가 다음 단계로 변경되고 (대기중→준비중→완료), 변경이 즉시 반영된다

- Then: 해당 테이블 카드가 색상 변경 또는 애니메이션으로 시각적으로 강조된다

## AS-07: 테이블 초기 설정
**As a** 관리자 (박서연),

**So that** 고객이 해당 테이블에서 자동 로그인하여 주문할 수 있다.

- When: 테이블 번호와 비밀번호를 입력하고 설정 버튼을 클릭한다
- Then: 테이블이 등록되고, 해당 정보로 태블릿에서 자동 로그인이 가능해진다

## AS-08: 주문 삭제
**As a** 관리자 (박서연),
**I want** 잘못된 주문을 삭제하기를,
**So that** 주문 오류를 즉시 수정하고 정확한 주문 금액을 유지할 수 있다.

### Acceptance Criteria
**Scenario 1: 주문 삭제**
- Given: 테이블의 주문 상세 화면이 표시된 상태
- When: 특정 주문의 삭제 버튼을 클릭한다
- Then: 확인 팝업이 표시된다

**Scenario 2: 삭제 확인**
- Given: 삭제 확인 팝업이 표시된 상태
- When: 확인 버튼을 클릭한다
- Then: 주문이 삭제되고, 테이블 총 주문액이 재계산되며, 성공 피드백이 표시된다

**Scenario 3: 삭제 취소**
- Given: 삭제 확인 팝업이 표시된 상태
- When: 취소 버튼을 클릭한다
- Then: 팝업이 닫히고, 주문은 그대로 유지된다

## AS-09: 테이블 이용 완료 처리
**As a** 관리자 (박서연),
**I want** 고객이 떠난 후 테이블 이용 완료 처리를 하기를,
**So that** 해당 세션의 주문이 과거 이력으로 이동하고, 새 고객이 깨끗한 상태에서 시작할 수 있다.

### Acceptance Criteria
**Scenario 1: 이용 완료 처리**
- Given: 테이블에 현재 세션 주문이 있는 상태
- When: 이용 완료 버튼을 클릭한다
- Then: 확인 팝업이 표시된다

**Scenario 2: 이용 완료 확인**
- Given: 이용 완료 확인 팝업이 표시된 상태
- When: 확인 버튼을 클릭한다
- Then: 현재 세션의 주문 내역이 과거 이력으로 이동하고, 테이블의 현재 주문 목록과 총 주문액이 0으로 리셋되며, 성공 피드백이 표시된다

**Scenario 3: 새 고객 시작**
- Given: 이용 완료 처리가 된 테이블 상태
- When: 새 고객이 태블릿에서 주문을 시작한다
- Then: 이전 주문 내역 없이 새로운 세션으로 시작된다

## AS-10: 과거 주문 내역 조회

- Then: 해당 테이블의 과거 주문 목록이 시간 역순으로 표시되며, 각 주문의 번호, 시각, 메뉴 목록, 총 금액, 이용 완료 시각이 표시된다

**Scenario 3: 대시보드 복귀**
- Given: 과거 주문 내역 화면이 표시된 상태

- Then: 대시보드 화면으로 복귀한다

## AS-11: 메뉴 등록
**As a** 관리자 (박서연),
**I want** 새로운 메뉴를 등록하기를,
**So that** 고객이 새 메뉴를 주문할 수 있다.

### Acceptance Criteria
**Scenario 1: 메뉴 등록 성공**
- Given: 메뉴 관리 화면이 표시된 상태
- When: 메뉴명, 가격, 설명, 카테고리, 이미지 URL을 입력하고 등록 버튼을 클릭한다
- Then: 메뉴가 등록되고, 메뉴 목록에 새 메뉴가 표시된다

**Scenario 2: 필수 필드 누락**
- Given: 메뉴 등록 화면이 표시된 상태
- When: 필수 필드(메뉴명, 가격, 카테고리)를 비우고 등록을 시도한다
- Then: 필수 필드 입력 안내 메시지가 표시되고, 등록이 진행되지 않는다

**Scenario 3: 가격 범위 검증**
- Given: 메뉴 등록 화면이 표시된 상태
- When: 유효하지 않은 가격(음수, 0 등)을 입력하고 등록을 시도한다
- Then: 가격 범위 오류 메시지가 표시되고, 등록이 진행되지 않는다

---

# INVEST 기준 검증

| 기준 | 설명 | 충족 여부 |
|------|------|:---------:|
| **Independent** | 각 스토리는 독립적으로 구현 가능 | ✅ |
| **Negotiable** | 구현 세부사항은 협상 가능 | ✅ |
| **Valuable** | 각 스토리는 사용자에게 가치 제공 | ✅ |
| **Estimable** | 각 스토리의 작업량 추정 가능 | ✅ |
| **Small** | 세부 기능별로 분리되어 적절한 크기 | ✅ |
| **Testable** | Given/When/Then AC로 테스트 가능 | ✅ |
